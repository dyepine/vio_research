# План экспериментов outdoor stereo–VIO

## Цель

Начать с одного воспроизводимого эксперимента: ORB-SLAM3 в режиме stereo–VI на GrandTour Alphasense ALB-2. Использовать VSLAM-LAB, не разрабатывать отдельный бенчмарк-фреймворк.

## 1. Подключить внешний SSD

- Желательно 500 ГБ; для работы преимущественно под Linux удобно использовать ext4.
- Проверить фактический свободный объём и стабильность подключения.
- Выбрать постоянную точку монтирования.
- Форматирование выполнять только после проверки содержимого и отдельного подтверждения: оно уничтожает данные.

## 2. Перенести данные

- Сначала копировать, не удаляя исходные файлы.
- Перенести подготовленные датасеты и результаты с проверкой целостности.
- После проверки обновить пути хранения через YAML — без дублирования настроек в Makefile и CLI.
- Убедиться, что VSLAM-LAB использует новые пути и видит подготовленную последовательность.
- Удалять исходную копию только после успешной проверки и подтверждения.

## 3. Проверить входы перед повторным запуском

- Проверить timestamps, порядок и пропуски измерений IMU.
- Проверить совпадение времени левого и правого изображений.
- Использовать только непрерывное окно камер, обеспеченное измерениями IMU; исключения на границах явно записывать в отчёт.
- Выполнено: исправлена ошибка передачи границы `rgb_idx`. VSLAM-LAB принимает включительную конечную границу; launcher теперь передаёт `[2, 5218]`, а режим `audit` проверяет фактическую выборку.
- После фильтрации проверить фактические timestamps и количество кадров, не полагаясь только на параметры команды.
- Проверить модель камер, масштабирование intrinsics, stereo- и camera–IMU extrinsics.
- Проверить систему координат выходной траектории и эталона. При необходимости преобразовать позы камеры в систему IMU.
- Подтвердить наличие настоящих GNSS/INS-поз. Не использовать fallback с позициями призмы и единичными quaternion как полноценный 6DoF-эталон.
- Эталонные данные не должны передаваться алгоритму.

## 4. Повторить первый эксперимент

Настройки эксперимента:

- Датасет: `grandtour-alphasense`, последовательность `alb_2`.
- Метод: ORB-SLAM3.
- Режим: `stereo-vi`.
- Визуализатор: отключён.
- Loop closure: отключён.
- Параметры задаются через YAML.

Перед запуском:

- Освободить RAM, закрыв ненужные тяжёлые приложения.
- Сохранить логи незавершённой попытки отдельно, не перезаписывать их.
- Зафиксировать версии, параметры, выбранное временное окно и аппаратную конфигурацию.

Критерий завершения: нормальный выход процесса, непустая траектория и проверенное временное покрытие. Само наличие файла с траекторией недостаточно.

## 5. Оценить результат

- Сравнить с GNSS/INS после приведения поз к одной системе координат.
- Использовать жёсткое SE(3)-выравнивание **без коррекции масштаба**.
- Не использовать стандартную оценку VSLAM-LAB без адаптации: в просмотренной реализации она включает scale correction (`-as`).
- Рассчитать абсолютную ошибку положения и, при корректном 6DoF-эталоне, ошибки ориентации и относительного движения.
- Указать допуск временного сопоставления, число сопоставленных поз и ограничения эталона.
- Проверить потери трекинга, сбросы и создание новых карт. Не смешивать независимые карты как одну непрерывную траекторию без анализа.
- Различать временное покрытие ключевых кадров и долю успешно обработанных изображений: это разные показатели.
- Сохранить wall time, CPU time и пиковую память процесса. Различать время обработки и ожидание при воспроизведении.

Один запуск на загруженном компьютере — проверка работоспособности, а не надёжный сравнительный бенчмарк производительности.

## 6. Расширить сравнение

Только после успешного первого эксперимента:

1. Добавить вторую outdoor-последовательность с отличающимися условиями, например BotanicGarden `1018-00`, проверив доступность нужного режима в VSLAM-LAB.
2. Выбрать второй метод с подтверждённой поддержкой stereo–IMU либо явно обозначить различие входных модальностей.
3. Согласовать единый протокол: входные данные, временные окна, loop closure, выравнивание, повторные запуски и учёт отказов.
4. Сравнивать точность вместе с покрытием, устойчивостью и вычислительными затратами, не исключая неудачные запуски из отчёта.

## Основные файлы

- `configs/datasets/prepare.yaml` — существующие настройки хранения и пользовательского экспортера. Его текущий ALB-2 относится к ZED2i, а не к Alphasense; это другой путь подготовки.
- `configs/experiments/grandtour_alb2_sequences.yaml` — выбор Alphasense-последовательности для VSLAM-LAB.
- `configs/experiments/grandtour_alb2_orbslam3.yaml` — настройки первого эксперимента.
- `configs/methods/orbslam3_stereo_vi.yaml` — настройки ORB-SLAM3, включая отключение loop closure.
- `scripts/run_grandtour_alb2.py` — внешняя обвязка VSLAM-LAB без изменений его исходников и глобальных путей; `make run` запускает её с настройкой окружения.
- `scripts/check_vio_inputs.py` — проверки камер/IMU и выбор общего временного окна. Режим обвязки `audit` только проверяет входные CSV; точное совпадение выходного `rgb_exp.csv` проверяется при запуске.
- `results/grandtour-alb2/` — аудит входов, provenance и логи незавершённой попытки.
