# План экспериментов outdoor stereo–VIO

## Цель

На чистой Linux-машине одной командой скачать и подготовить весь выбранный набор,
затем без ручной конвертации запустить совместимый метод из каталога VSLAM-LAB.
Переиспользовать VSLAM-LAB, ROS и evo; отдельный бенчмарк-фреймворк не разрабатывать.
Прежний эксперимент ALB-2 ниже сохраняется как история.

## Решение о переезде датасетов — 2026-10-12

Целевой путь подготовки зафиксирован в [плане переезда](docs/dataset-migration.md).
GrandTour переводим на штатный `grandtour-alphasense`: основной набор KÄB-1 и
ALB-1, LMB-2 — дополнительная, HÖB-1 — сложный случай для устойчивости; RIV-1
исключена из HF-пути. Старый эксперимент ALB-2 и его данные сохраняются.
BotanicGarden интегрируем как `DatasetVSLAMLAB` adapter по официальному гайду:
сначала `1018_00`, затем `1018_13`; `1005_00` остаётся дополнительным кандидатом.
Конвертацию прежнего `scripts/prepare.py` перенесли в hooks адаптера:
стандартный layout VSLAM-LAB и GT в body frame Xsens, с переиспользованием
скачанных VLIO bags и corrected GT. EuRoC-like exporter удалён после
приёмки нового импорта. Наш протокол evo без коррекции масштаба сохраняется.
Уточнение от 2026-10-13: GrandTour оцениваем относительно штатного GNSS/INS GT;
призма и Holistic Fusion не входят в обязательную подготовку и приёмку переезда.
`make prepare` включает bootstrap и все четыре записи; `make run METHOD=... MODE=...`
вызывает штатный pipeline. По последнему решению пользователя адаптер поставляется
через fork `dyepine/VSLAM-LAB`, ветка `vio-research-datasets`, закреплённый submodule
commit `6a865b197e7d3fa5d952412bc1905159e3cbaabe`. Патч и его применение удалены;
PR в upstream не планируется. BotanicGarden
1018_00, KÄB-1 и ALB-1 проверены; загрузка 1018_13 ещё идёт.
Последующие разделы описывают текущий/предыдущий ALB-2
эксперимент и эксплуатационные ограничения, а выбор нового набора задаёт план переезда.

### Текущее управление окружением

- Общие defaults: `scripts/env.sh`. `make configure` или первая команда Makefile создаёт из него `.envrc`; существующий файл никогда автоматически не перезаписывается.
- `.envrc` игнорируется Git. Настройки T7 перенесены туда; прежние локальные YAML сохранены вне репозитория как резервные копии и больше не используются.
- Выбор эксперимента задаётся `VIO_EXPERIMENT_CONFIG` в `.envrc`, путь больше не зашит в обвязке. `PYTHON` задаёт bootstrap-интерпретатор для `.venv`; Python окружения Pixi не меняется. Команды, зависимости и служебные пути остаются в Makefile.
- Публикуемые YAML используют `${VIO_DATA_DIR}` и `${VIO_RESULTS_DIR}`. Отсутствующие переменные вызывают явную ошибку; Makefile сам читает `.envrc`, direnv не обязателен.
- `VIO_RESULTS_DIR` — постоянный корень результатов. Каждый запуск автоматически получает папку `YYYY-MM-DD_HH-MM-SS` (локальное время), при совпадении — суффикс `-02`, `-03` и т. д. Каталог создаётся атомарно, старые результаты не перезаписываются; путь выводится в терминал и фиксируется в provenance. Локальный корень T7 обновлён; старые retry-каталоги сохранены.
- Проблема T7 остаётся блокером; длительный прогон не запускался. Пройдены 27 offline-тестов, включая совпадение дат, параллельное создание папок, передачу выбранного эксперимента и создание окружения выбранным интерпретатором.
- Пройдены 21 offline-тест, включая создание/сохранение `.envrc`, переменные путей и вызов `make run` с тестовым Pixi. Исходники VSLAM-LAB не изменялись.

### Подготовка публичного репозитория

- VSLAM-LAB оформлен как Git submodule, ревизия `7595da8e516ec8b7e3194d1b9fa9dc01718b513c`. Прежние локальные изменения `path_constants.py` сохранены вне репозитория, затем файл возвращён к upstream-версии; submodule чистый.
- На этапе публикации настройки T7 были сохранены в игнорируемых `*.local.yaml`; впоследствии эта схема заменена на `.envrc` (см. выше). Датасеты, результаты, `.venv`, `.tools` и кеш не включаются в Git.

### Упрощение интеграции

- `make run` вызывает внешнюю обвязку существующих API VSLAM-LAB. Начатые изменения CLI фреймворка отменены; прежний локальный `path_constants.py` сохранён без новых изменений.
- Обвязка задаёт пути только на объектах датасета и эксперимента; глобальные константы фреймворка больше не подменяются. Форматы входов и генерация калибровки/CSV остаются штатными.
- Проверки камер/IMU вынесены в `scripts/check_vio_inputs.py`. Запуск больше не зависит от эталона GNSS/INS и не копирует его; его происхождение, валидность и система координат должны проверяться отдельно перед оценкой.
- Сохранены точная проверка выборки кадров, таймаут 900 с, защита RAM, замер `/usr/bin/time`, код выхода и отчёты. На этом этапе `ResultsDir` требовалось менять вручную; теперь это постоянный корень для автоматически датированных запусков. Режим `prepare` у старого launcher удалён; подготовленные входы подаются отдельно.
- Пройдены 16 offline-тестов. На внутренней копии датасета проверены реальные функции VSLAM-LAB для калибровки, CSV (5217 кадров) и команды запуска; выполнение алгоритма в этой проверке подменено тестовым вызовом. Подтверждено отсутствие изменений глобальных путей и файлов фреймворка. Новый длительный прогон не запускался.

### Предыдущая попытка

- VSLAM-LAB установлен в `external/VSLAM-LAB`, ревизия `7595da8e516ec8b7e3194d1b9fa9dc01718b513c`.
- Установлены Pixi и окружения `vslamlab` и `orbslam3`; используется готовый пакет ORB-SLAM3.
- GrandTour Alphasense `alb_2` скачан и подготовлен. Данные занимают около 4,6 ГБ.
- Начат headless-прогон stereo–VI с отключённым loop closure.
- VSLAM-LAB остановил процесс по защитному порогу: занято более 95% оперативной памяти.
- Завершённой траектории и метрик точности нет. Логи сохранены в `results/grandtour-alb2/`.

**Внешний SSD решит вопрос хранения, но не нехватку RAM. Перед повторным запуском нужно освободить оперативную память. Защитный порог отключать не следует.**

## 1. Подключить внешний SSD

- Желательно 500 ГБ; для работы преимущественно под Linux удобно использовать ext4.
- Проверить фактический свободный объём и стабильность подключения.
- Выбрать постоянную точку монтирования.
- Форматирование выполнять только после проверки содержимого и отдельного подтверждения: оно уничтожает данные.

## 2. Перенести данные

- Сначала копировать, не удаляя исходные файлы.
- Перенести подготовленные датасеты и результаты с проверкой целостности.
- После проверки обновить машинные пути в `.envrc`; YAML ссылаются на них без дублирования настроек в Makefile и CLI.
- Убедиться, что VSLAM-LAB использует новые пути и видит подготовленную последовательность.
- Удалять исходную копию только после успешной проверки и подтверждения.

## 3. Проверить входы перед повторным запуском

- Проверить timestamps, порядок и пропуски измерений IMU.
- Проверить совпадение времени левого и правого изображений.
- Использовать только непрерывное окно камер, обеспеченное измерениями IMU; исключения на границах явно записывать в отчёт.
- Выполнено: исправлена ошибка передачи границы `rgb_idx`. VSLAM-LAB принимает включительную конечную границу; launcher теперь передаёт `[2, 5218]`, а режим `audit` проверяет фактическую выборку.
- После фильтрации проверить фактические timestamps и количество кадров, не полагаясь только на параметры команды.
- Проверить модель камер, масштабирование intrinsics, stereo- и camera–IMU extrinsics.
- Проверить систему координат выходной траектории и эталона. При необходимости преобразовать позы камеры в систему IMU.
- Подтвердить наличие настоящих GNSS/INS-поз. Не использовать fallback с позициями призмы и единичными quaternion как полноценный 6DoF-эталон.
- Эталонные данные не должны передаваться алгоритму.

## 4. Повторить первый эксперимент

Настройки эксперимента:

- Датасет: `grandtour-alphasense`, последовательность `alb_2`.
- Метод: ORB-SLAM3.
- Режим: `stereo-vi`.
- Визуализатор: отключён.
- Loop closure: отключён.
- Параметры задаются через YAML.

Перед запуском:

- Освободить RAM, закрыв ненужные тяжёлые приложения.
- Сохранить логи незавершённой попытки отдельно, не перезаписывать их.
- Зафиксировать версии, параметры, выбранное временное окно и аппаратную конфигурацию.

Критерий завершения: нормальный выход процесса, непустая траектория и проверенное временное покрытие. Само наличие файла с траекторией недостаточно.

## 5. Оценить результат

- Сравнить с GNSS/INS после приведения поз к одной системе координат.
- Использовать жёсткое SE(3)-выравнивание **без коррекции масштаба**.
- Не использовать стандартную оценку VSLAM-LAB без адаптации: в просмотренной реализации она включает scale correction (`-as`).
- Рассчитать абсолютную ошибку положения и, при корректном 6DoF-эталоне, ошибки ориентации и относительного движения.
- Указать допуск временного сопоставления, число сопоставленных поз и ограничения эталона.
- Проверить потери трекинга, сбросы и создание новых карт. Не смешивать независимые карты как одну непрерывную траекторию без анализа.
- Различать временное покрытие ключевых кадров и долю успешно обработанных изображений: это разные показатели.
- Сохранить wall time, CPU time и пиковую память процесса. Различать время обработки и ожидание при воспроизведении.

Один запуск на загруженном компьютере — проверка работоспособности, а не надёжный сравнительный бенчмарк производительности.

## 6. Расширить сравнение

Только после успешного первого эксперимента:

1. Добавить вторую outdoor-последовательность с отличающимися условиями, например BotanicGarden `1018-00`, проверив доступность нужного режима в VSLAM-LAB.
2. Выбрать второй метод с подтверждённой поддержкой stereo–IMU либо явно обозначить различие входных модальностей.
3. Согласовать единый протокол: входные данные, временные окна, loop closure, выравнивание, повторные запуски и учёт отказов.
4. Сравнивать точность вместе с покрытием, устойчивостью и вычислительными затратами, не исключая неудачные запуски из отчёта.

## Основные файлы

- `configs/datasets/prepare.yaml` — прежние настройки хранения и пользовательского экспортера (удалены при миграции). Его текущий ALB-2 относится к ZED2i, а не к Alphasense; это другой путь подготовки.
- `configs/experiments/grandtour_alb2_sequences.yaml` — выбор Alphasense-последовательности для VSLAM-LAB.
- `configs/experiments/grandtour_alb2_orbslam3.yaml` — настройки первого эксперимента.
- `configs/methods/orbslam3_stereo_vi.yaml` — настройки ORB-SLAM3, включая отключение loop closure.
- `scripts/run_grandtour_alb2.py` — внешняя обвязка VSLAM-LAB без изменений его исходников и глобальных путей; `make run` запускает её с настройкой окружения.
- `scripts/check_vio_inputs.py` — проверки камер/IMU и выбор общего временного окна. Режим обвязки `audit` только проверяет входные CSV; точное совпадение выходного `rgb_exp.csv` проверяется при запуске.
- `results/grandtour-alb2/` — аудит входов, provenance и логи незавершённой попытки.

## Ближайший шаг

Проверить кабель/USB-порт и стабильность подключения T7, затем согласовать безопасную проверку файловой системы (без ремонта смонтированного тома). После устранения проблемы повторно проверить целостность скопированных данных и сохранить логи неудачной попытки. Только затем запускать прогон; новая датированная папка внутри `VIO_RESULTS_DIR` создаётся автоматически. Старые данные не удалять, диск не форматировать и ремонт файловой системы не выполнять без отдельного подтверждения.

### Интеграция оценки evo

Самописные association/SE3/ошибки заменены evo; `make evaluate` сохраняет
отдельный протокол и стандартные ZIP, `make visualize` читает сохранённую оценку.
RPE считается внутри непрерывных участков по расстоянию GT. Оценка реального
ORB-SLAM3 результата остаётся непроверенной до получения экспортированной траектории
и подтверждения её frame semantics. Новый прогон алгоритма здесь не требуется.
