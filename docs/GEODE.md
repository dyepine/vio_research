# GEODE Offroad γ

Адаптер находится в submodule VSLAM-LAB: `Datasets/dataset_files/dataset_geode.py`.
Имя датасета — `geode-gamma`; подготовлены `offroad1` и `offroad1_raw_radtan4`.
Поддерживаются `mono`, `stereo`, `mono-vi`, `stereo-vi`.
Для основной таблицы используется ректифицированная `offroad1`;
источники и SE3-оценки сохранены в [artifacts/report](../artifacts/report/README.md).
Остальные варианты приведены после основного описания.

## Ректифицированный вариант

Для сравнения ORB-SLAM3, OKVIS 1 и Voxel-SVIO в stereo-inertial режиме:

```bash
make run CONFIG=configs/experiments/geode_orbslam3_okvis1_voxel_svio.yaml
# Короткая проверка на 200 кадрах:
make run CONFIG=configs/experiments/geode_orbslam3_okvis1_voxel_svio.yaml RGB_MAX=200
```

Конфиг задаёт один прогон каждого метода, общий IMU noise profile из gamma
calibration, отключённый loop closure и оценку с SE3 alignment без подгонки
масштаба. Общий интервал camera–IMU определяется загрузчиком автоматически.

```bash
make prepare CONFIG=configs/experiments/geode_orbslam3_okvis1_voxel_svio.yaml
```

По умолчанию запись сохраняется в
`${VIO_DATA_DIR}/VSLAM-LAB-Benchmark/GEODE-GAMMA/offroad1`, исходники — рядом в
`GEODE-GAMMA/raw`. Можно переиспользовать уже скачанные исходники без копирования:

```bash
GEODE_SOURCE_DIR=/path/to/geode/raw make prepare CONFIG=configs/experiments/geode_orbslam3_okvis1_voxel_svio.yaml
```

Каталог исходников должен содержать `Offroad1_gamma.bag`, `gamma_config.yaml` и
`Offroad1.txt`; отсутствующие файлы адаптер скачивает сам. Bag проверяется по
размеру и опубликованному Drive MD5; калибровка и reference — по закреплённым
SHA256. Частичные сетевые загрузки сохраняются как `.part`. Повтор команды
возобновляет принадлежащий адаптеру импорт; готовность отмечается только после
завершения всех этапов. Повреждённые файлы не удаляются автоматически.

Подготовка версии 1 с отдельной stereo matrix автоматически переносится в
`offroad1.rectification-v1`, после чего изображения создаются заново из уже
сохранённого bag с цепочкой camera–IMU (версия 2). Резервный каталог не
перезаписывается. Сохранённые результаты старых запусков относятся к прежним
изображениям; сравнение методов после исправления требует нового запуска
всех методов на одной версии подготовки.

Исходный bag занимает 3,205 GB. Консервативная оценка подготовки — около
17,1 GB вместе с исходниками и двумя потоками полноразмерных серых PNG.
Это оценка дискового пространства, а не объём скачивания. Для выбора только
этой записи служит отдельный YAML; действующие experiments и default selection
не изменены.

Полный импорт проверен 18 октября 2026: 4049/4049 исходных кадров образовали
4049 пар без пропусков, максимальная разница timestamps — 0,886201 ms;
40 492 IMU samples, 42 626 reference poses. Реальный объём всего `GEODE-GAMMA`
с сохранёнными исходниками после исправления ректификации — около **7,09 GB**
(ещё 3,86 GB занимает сохранённая подготовка версии 1, если она существовала).
Штатная проверка camera–IMU
window допускает 4048 кадров, начиная со второго: первый не имеет строгого
двустороннего IMU bracket. Это проверка импорта, а не результат запуска VIO.

## Преобразование данных

* Камеры: `/left_camera/image/compressed` и `/right_camera/image/compressed`,
  nominal 10 Hz. Используется `header.stamp` с точностью до наносекунд.
* IMU: **внешний Xsens MTi-30 `/imu/data`**, nominal 100 Hz. `/livox/imu`
  относится к другому датчику и не используется. Единицы: rad/s и m/s².
* JPEG декодируется в BGR, затем переводится в grayscale и ректифицируется.
  Размер выхода 1224×1024; `stereoRectify(alpha=0, CALIB_ZERO_DISPARITY)`
  сохраняет размер, но меняет FoV/фокусные параметры для общей области стерео.
  Все пять исходных коэффициентов `[k1,k2,p1,p2,k3]` участвуют в обработке.
  На выходе pinhole-геометрия без дисторсии, записанная как `cam_model: pinhole`,
  `distortion_type: radtan4`, `[0,0,0,0]` для совместимости с бинарным reader
  ORB-SLAM3. Это точное представление ректифицированной камеры; исходный `k3`
  участвует в ректификации и не отбрасывается.
* `rgb.csv` содержит упорядоченные пары ближайших timestamps с допуском 2 ms,
  без повторного использования правого кадра. Это допуск ассоциации, а не
  утверждение точности аппаратной синхронизации. Пропуски и максимальное
  расхождение записываются в `stereo_report.json`.
* Исходный YAML состоит из повторяющихся секций камер и содержит два
  `gyro_std`. Камеры читаются отдельно; первый `gyro_std` трактуется как
  white noise, второй — как random walk согласно соседним комментариям.
  Noise переносится в continuous-time convention imu_utils без умножения
  на частоту. Приоры bias/saturation не придумываются.

`rectification.json` фиксирует параметры, действительно использованные ROS1
экстрактором, и версию OpenCV. Из этого файла создаётся `calibration.yaml`,
поэтому различие версий OpenCV основного и ROS1 окружений не меняет геометрию
между сохранёнными изображениями и калибровкой.

## Системы координат и ограничения оценки

Конвенция: `T_A_B` переводит координаты B в A. Body адаптера — опубликованная
**beta reference frame**, в которой дана Offroad GT. IMU имеет ненулевой `T_BS`;
нельзя считать его тождественным преобразованием.

Численное межустановочное преобразование взято из авторского
[`gamma2GT_gnss.py` на закреплённой ревизии](https://github.com/PengYu-Team/GEODE_dataset/blob/c6e930623d4fed450d7fc50e16e3ffe0288b692b/script/gamma2GT_gnss.py).
Для gamma device используется LiDAR frame, как в авторской оценке LIO:

```
T_world_beta = T_world_gamma_lidar @ inverse(T_beta_gamma_lidar)
T_beta_imu = T_beta_gamma_lidar @ inverse(T_IMU_LiDAR)
T_imu_left = T_IMU_CamL
T_imu_right = T_IMU_CamR
T_right_left = inverse(T_imu_right) @ T_imu_left
T_beta_rect_camera = T_beta_imu @ T_imu_camera @ T_camera_rect_camera
```

Кватернион межустановочного преобразования нормируется перед получением
матрицы вращения. Независимые цепочки опубликованной калибровки расходятся:
stereo из двух camera–IMU transforms отличается от отдельной stereo calibration
примерно на 5,56 mm / 0,69°. Используется согласованная цепочка из **двух
camera–IMU transforms**; отдельная `T_CamR_CamL` не используется для пикселей.
На контрольной исходной паре из bag медиана вертикального расхождения
геометрически согласованных SIFT-соответствий — около 0,39 px, p90 — 1,10 px;
отдельная stereo calibration давала медиану 16,47 px. Это локальная проверка
эпиполярной геометрии, не измерение точности траектории или всего датасета.
Дополнительная проверка уже подготовленных пар №0, 199, 999, 2000 и 4048 дала
медианы 0,43–0,77 px и p90 1,01–1,31 px. Первая исходная пара с provenance
сохранена в test fixtures, чтобы регрессия проверяла реальные соответствия,
а не только алгебраическую согласованность матриц.
Baseline выбранной цепочки — около 0,19354 m. Расхождение с альтернативной
калибровкой фиксируется в `calibration_metadata.json`.
LiDAR–camera цепочка не используется вместо прямой camera–IMU калибровки.
Это воспроизводимая начальная конвенция, **не независимая проверка точности
межустановочной калибровки**. Перед окончательной публикацией APE/RPE её нужно
проверить на реальных оценённых траекториях/у автора датасета.

Reference — опубликованная GNSS/INS-RTK `Offroad1.txt`, 6DoF, не результат
визуального SLAM. В исходнике 42 626 поз и 880 соседних инверсий времени.
`groundtruth.csv` стабильно сортируется по исходному timestamp, сохраняя все
позы и времена. Повторные timestamps, нечисловые позы и неверные кватернионы
отклоняются. Исходный TXT сохраняется без изменений. Сортировка — политика
сериализации для загрузчика, **не доказанное исправление исходных времён**.
Координаты подготовленного GT локальные: из каждой позиции вычитается позиция
первой по времени GT-позы (`p_local = p_source - p_first`). Направления осей,
масштаб в метрах и timestamps сохраняются; начало выбирается по
всему исходному GT, а не по первому кадру или первому совпадению при оценке.
Это только перенос мировой системы координат, без нормирования расстояний
или совмещения с оценкой SLAM. Исходный TXT остаётся в `raw/`, а смещение,
timestamp начала и версия преобразования записываются в `reference_metadata.json`.
Обычный `make prepare` обновляет GT ранее подготовленных последовательностей
без повторного извлечения изображений и IMU. Обе последовательности используют
одинаковое начало. Сохранённые результаты запусков и их копии GT не изменяются.
Ориентации исходного TXT (`qx qy qz qw`) преобразуются отдельно:
`R_new = Rz(90°) Rx(180°) R_source Rx(180°)`. Для extrinsic xyz Euler это
`roll_new = roll`, `pitch_new = -pitch`, `yaw_new = 90° - yaw`. Реализация
работает через композицию вращений и нормализованные кватернионы, без Euler
сингулярностей. Координаты позиций при этой поправке не поворачиваются.
Дополнительный подобранный bias не применяется. Версия и формула записываются
в `reference_metadata.json` (`orientation_convention_version: 1`). Обычный
`make prepare` обновляет ранее подготовленный GT из исходного TXT; повторная
подготовка не применяет поправку второй раз. Это принятое в пайплайне соглашение,
поддержанное проверками гироскопа и сохранённых траекторий; исходное соглашение
GNSS/INS независимо не подтверждено. Пересчёт старых запусков требует отдельного
явного обновления их копий GT: подготовка датасета их не изменяет.
Эта особенность отражается в `reference_metadata.json` и отчёте подготовки;
датасет пока следует считать предварительным для строгого метрического сравнения.
У авторов также открыты [issue #19 о внешней калибровке γ](https://github.com/PengYu-Team/GEODE_dataset/issues/19)
и [issue #5 о timestamps reference](https://github.com/PengYu-Team/GEODE_dataset/issues/5).
В комментарии к #5 автор обещал заменить GT после обработки; проверяемый здесь
закреплённый файл всё ещё содержит описанные инверсии. Исправленная калибровка
в #19 не опубликована. Эти сообщения не устанавливают величину ошибки нашей
конкретной записи, но сохраняют основание для предварительного статуса оценки.

## Источники и проверка

* [Сайт GEODE](https://thisparticle.github.io/geode/).
* [Официальный код и правила приведения к GT](https://github.com/PengYu-Team/GEODE_dataset).
* [Offroad1 gamma bag](https://drive.google.com/file/d/1v70uMx5GcjSpvLxA0YsEN6_wX7zK7yHT/view).
* [Калибровка Drive](https://drive.google.com/file/d/1GheigvWF1YTTw-2y4XrN4f-5i5wh2m4s/view).
* [Reference](https://drive.google.com/file/d/15sbhriCWbvfBloe8qJOJPhBsda9eD7Mg/view).

Используется именно Drive calibration: версия в GitHub отличается названиями
топиков, ключом/единицами stereo transform и содержит дополнительный повторный
ключ. Автоматическое переключение между этими версиями не выполняется.
Готовый stereo-VI адаптер GEODE для VSLAM-LAB при поиске не найден; реализация
использует штатный dataset lifecycle, существующий checksum downloader и
алгоритм timestamp pairing из соседнего адаптера.

`tests/migration/test_geode.py` проверяет чтение реальной калибровки, согласованность
ректифицированной геометрии, точность времён, отклонение испорченного GT,
ассоциацию при пропущенном кадре, возобновление и фактическое извлечение из
синтетического ROS1 bag. Результаты реального импорта — в каталоге данных,
`preparation_report.json`; они не означают, что выполнен benchmark VIO.

После исправления формата дисторсии и ректификации выполнен полный повтор
`comparison_20261018T180553_eb3936a1`: все три процесса завершились успешно,
сохранено 1501 поза ORB-SLAM3, 4048 OKVIS 1 и 3915 Voxel-SVIO. Проверены
монотонность времён, конечность поз и нормы кватернионов. На пяти распределённых
стереопарах дополнительно проверена эпиполярная геометрия. Методы запускались
с `JOBS=3`, поэтому их runtime не является измерением изолированного быстродействия.
Это проверка исполнения; точность относительно GT здесь не оценивалась.

## Дополнительные варианты камеры

## Исходная radtan5 для ORB-SLAM3 и OKVIS 1

`offroad1_raw_radtan5` использует исходные опубликованные `fx, fy, cx, cy` и
`[k1,k2,p1,p2,k3]` без подбора параметров. Геометрия и значения grayscale
пикселей совпадают с `offroad1_raw_radtan4`; меняется калибровка.
Готовые PNG переиспользуются через жёсткие ссылки, а на exFAT — через точные
байтовые копии. Старые варианты не перезаписываются. Восстанавливать геометрию
из ректифицированных изображений этот путь не пытается.

```bash
make prepare CONFIG=configs/experiments/geode_raw_radtan5_orbslam3_okvis1.yaml
make run CONFIG=configs/experiments/geode_raw_radtan5_orbslam3_okvis1.yaml JOBS=1
```

Проверка первых 500 пар выполнена в
`comparison_20261019T151244_0c403961`: оба процесса завершились; 182 позы ORB
и 500 OKVIS. APE позиции RMSE: 0.1243 м и 0.5129 м соответственно, SE3 без
масштаба. Чтение обоих исходных k3 подтверждено логом ORB, точное D8 — фактическим
native YAML OKVIS. Это проверка интеграции на коротком участке, не полный прогон.

ORB-SLAM3 получает radtan5; его stereo-фронтенд сам ректифицирует изображения.
Адаптер OKVIS 1 точно представляет исходную radtan5 моделью `radialtangential8`:
`[k1,k2,p1,p2,k3,0,0,0]`. Нули относятся к знаменателю рациональной модели,
исходный `k3` сохраняется. Геометрические тесты сверяют D5/D8 через OpenCV.
Код оценивателя OKVIS не меняется; меняется только передача калибровки.
Шумы IMU, приоры OKVIS, extrinsics и протокол сохранены из GEODE-сравнения.

sqrtVINS в закреплённой ревизии не принимает эту модель: CamBase хранит
4 intrinsics + 4 distortion, CamRadtan не содержит радиального члена k3*r^6.
Нужны изменения нативной модели, чтения и якобианов; добавление пятого числа
в YAML недостаточно. Он не включён в этот конфиг, его исходники не менялись.

## Вариант с исходной геометрией и приближением radtan4

Последовательность `offroad1_raw_radtan4` использует те же сообщения bag,
timestamps, IMU, reference и исходные camera–IMU transforms. JPEG декодируется
в BGR и переводится в серый PNG **без undistort, rectification, crop или resize**.
Геометрия пикселей остаётся исходной. Внутри конкретного SLAM может выполняться
собственная ректификация; например, её выполняет стереофронтенд ORB-SLAM3.

```bash
make prepare CONFIG=configs/experiments/geode_raw_radtan4_orbslam3_okvis1_voxel_svio.yaml
make run CONFIG=configs/experiments/geode_raw_radtan4_orbslam3_okvis1_voxel_svio.yaml
```

Это отдельная подготовка рядом с ректифицированной `offroad1`. Bag и небольшие
исходники переиспользуются. Сопоставление методов, шумы IMU, число прогонов и
протокол оценки совпадают с ректифицированным экспериментом.
Подготовка занимает около 4,11 GB дополнительно; вместе с raw, ректифицированной
подготовкой и сохранённой версией 1 весь `GEODE-GAMMA` занимает около 15,06 GB.

Четырёхкоэффициентная модель подбирается к **опубликованной модели radtan5**,
а не к траектории или GT. Обучающая сетка — 121×101 равномерных координат по
всему исходному кадру. Целевая функция — невзвешенная сумма квадратов 2D
ошибок проекции в пикселях. Проверка — все 1 253 376 целочисленных координат
каждой камеры, включая границы и углы; отдельно записывается ошибка в полосе
10% от границ. Метрики ниже — евклидово расстояние между двумя проекциями.

| Вариант | Левая: RMS / max, px | Правая: RMS / max, px |
| --- | --- | --- |
| Просто удалить k3 | 0,773 / 5,901 | 1,242 / 9,757 |
| Подобрать D4, оставить K | 0,0609 / 0,732 | 0,0986 / 1,243 |
| **Подобрать K и D4 — выбран** | **0,0381 / 0,485** | **0,0618 / 0,827** |

В выбранном варианте p95 ошибки — 0,0565 px слева и 0,0914 px справа.
Изменяются `fx, fy, cx, cy, k1, k2, p1, p2`; физические преобразования камер
и IMU не подгоняются. Это приближение исходной калибровочной модели, не новая
физическая калибровка и не измерение точности VIO. Максимальная ошибка
у краёв существеннее средней; нулевой она не становится.

Код подбора — `Datasets/dataset_files/geode_radtan_fit.py` в submodule.
`radtan4_fit.json` в подготовленной последовательности содержит исходные и
подобранные параметры, все три сравниваемых варианта, ошибки по кадру/краям,
критерий подбора и SHA256 источника. Ошибки проверяются в регрессионном тесте;
отдельно проверено точное равенство сохранённых пикселей декодированному
изображению после перевода в серый, без геометрического преобразования.

В коротком запуске на 200 кадрах ORB-SLAM3 сохранил 32 позы, OKVIS 1 — 199.
Voxel-SVIO прочитал модель и успешно инициализировался, но процесс остановил
штатный глобальный лимит RAM (>95%); завершённым этот тест не считается.
Полный сравнительный VIO-прогон на этом варианте пока не выполнен.


## Дополнительный контроль Offroad7

Добавлена поддержка `offroad7` с отдельными bag/GT и общей опубликованной
калибровкой γ. После ручного скачивания пользователем проверены опубликованные
MD5 и подготовлены 1840 стереопар, 18410 IMU samples и 15133 GT-позы.
Полный контроль 2026-10-19:
`comparison_20261019T130235_8527686d`, 1839 входных пар, по одному запуску.
Оба процесса завершились, но траектории разошлись: APE позиции RMSE
3268.84 м (Voxel-SVIO) и 27125.59 м (sqrtVINS).
Из-за разрывов GT до 0.6134 с ассоциировано около 96.8% сохранённых поз;
прежние ограничения GNSS/INS-калибровки остаются. Контрольный конфиг —
`configs/experiments/geode_offroad7_sqrtvins_voxel_svio.yaml`: Voxel-SVIO и
sqrtVINS (окно 2 с), прежние GEODE шумы, SE3 без коррекции масштаба.
Подготовка и запуск: `make prepare CONFIG=...`, затем `make run CONFIG=... JOBS=1`.
Подробности доступа и возобновления —
`results/vio/diagnostics/geode_offroad7_20261019/README.md`.
