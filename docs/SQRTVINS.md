# sqrtVINS в VSLAM-LAB

Источник: [rpng/sqrtVINS](https://github.com/rpng/sqrtVINS), закреплённая ревизия
`30fafc89d89cfb896d06fdaa68fbda8545e02e9f`. Код оценивателя не изменён.
Репозиторий и build находятся в игнорируемом `Baselines/SqrtVINS`; интеграция —
в `Baselines/extra-files/sqrtvins` и `baseline_files/baseline_sqrtvins.py`.
Лицензия авторского кода — LGPL-3.0; исходные notices сохраняются в checkout.

```bash
make run CONFIG=configs/experiments/sqrtvins.yaml JOBS=1
make evaluate CONFIG=configs/experiments/sqrtvins.yaml EVAL_ARGS="--saved-protocol"
```

Конфиг запускает по одному stereo-VI прогону на GrandTour `kaeb_1`,
BotanicGarden `1018_13` и ректифицированном GEODE `offroad1`. Профили IMU
и протокол совпадают с основной матрицей `report.yaml`. Для всех трёх записей
задано `Settings.init_window_time: 2.0`, как в успешном контроле GrandTour
и прежнем GEODE-конфиге. В штатном профиле адаптера остаётся 0.15 s.
На BotanicGarden этот новый эксперимент ещё не проверен. Нативная сборка использует установленные системные CMake, Eigen3,
OpenCV и Boost filesystem/system/thread/date_time. При отсутствии бинарника
сборка запускается автоматически; системные пакеты скрипт не устанавливает.
Сборка последовательная (`-j1`), Release `-O1 -DNDEBUG`, float32 как
upstream `USE_FLOAT=1`. ROS, ROS master, playback и GUI не требуются.

Из upstream `config/euroc_mav/estimator_config_srvins.yaml` взяты параметры
фильтра и трекера. Явные отличия профиля: фиксированная калибровка, нулевые
начальные догадки bias вместо значений EuRoC, один поток OpenCV, синхронная
инициализация, отключённые общие init-log файлы в `/tmp`. В частности,
`init_dyn_use: false` сохранён из этого профиля: динамическая инициализация
в этой проверке не испытывалась. Это начальный профиль, не настройки,
оптимизированные под GEODE.

Камеры поддерживают pinhole+radtan4/equid4; ректифицированные камеры получают
четыре нулевых коэффициента. Radtan5 отвергается явно. Геометрия изображений
в адаптере метода не меняется. `T_imu_cam = inverse(T_BI) @ T_BC`; шумы и
gravity берутся из материализованного `calibration_exp.yaml`. `timeshift` равен
нулю, как в существующих GEODE профилях. Левый timestamp задаёт общее время
stereo-пары; допустимое расхождение с правым — менее 5 ms.

Наносекунды читаются как int64; общий origin вычитается до перевода в секунды.
Перед камерой IMU подаётся до первого sample строго после обоих timestamps.
Готовая ориентация Xsens и GT в оцениватель не подаются. Выходная IMU-поза
преобразуется в body: `R_WI = transpose(native R_GtoI)`,
`T_WB = T_WI @ inverse(T_BI)`. Сохраняется обычный VSLAM-LAB pose CSV.
В каждом прогоне записывается `sqrtvins_provenance_<iteration>.json` с ревизией,
float precision, hash бинарника/адаптера/входов и количеством сохранённых поз.

## Проверки и ограничения

Четыре теста адаптера проверяют геометрию при ненулевом IMU lever arm,
перенос intrinsics/noise, отказ от неподдерживаемой модели и читаемость YAML
через реальный OpenCV FileStorage.

Проверки реального GEODE завершились штатно:

* 200 входных stereo-пар → 73 позы после инициализации;
* 500 входных stereo-пар → 373 позы, стандартный evo evaluation завершился.

Результат 500 кадров находится в
`/tmp/geode-sqrtvins-smoke/comparison_20261019T082705_30cd5e98`.
В этом коротком прогоне траектория разошлась: APE позиции RMSE около 1173 m,
APE ориентации около 153°. Нативный лог содержит отбрасывания features
с отрицательной глубиной. Причина пока не установлена; завершение процесса
не подтверждает точность и не исключает ошибку интеграции. Полная
последовательность затем проверена с GEODE override 2.0 s, см. ниже;
raw-radtan4 вариант не запускался.

Полный прогон с окном 2.0 s:
`results/vio/VSLAM-LAB-Evaluation/comparison_20261019T090458_5d9038a0`.
Обработаны все 4048 пар, экспортированы 3923 позы, нормальное завершение за
250.4 s. Начальные 500 кадров побайтово воспроизводят успешную короткую
проверку с тем же окном. Далее оценка расходится: по всему прогону
APE позиции RMSE 29253.24 m, RPE позиции 1000.83 m, APE ориентации 56.30°,
RPE ориентации 2.87°. Оценка: сохранённый SE3-протокол без коррекции масштаба,
dt 0.05 s, GT с новой конвенцией ориентации. Увеличение окна исправляет
проверенный начальный участок, но не обеспечивает устойчивость полной записи.

```bash

external/VSLAM-LAB/.pixi/envs/vslamlab/bin/python -m unittest discover -s tests/migration -p test_sqrtvins.py -q
```
